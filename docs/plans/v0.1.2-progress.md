## Project memory

Shared lossless legacy/managed parsing, stable IDs, provenance, supersession,
diagnostics, exact-base edits, confined reads, local lexical selection,
desktop/CLI delivery, private settings and content-free receipts are implemented.
The Memory companion, `/memory`, context hint, search, edit/forget and explicit
suggestion acceptance/dismissal are wired.

New settings use a **768-byte/four-entry** ceiling, about 250 estimated tokens.
Existing settings retain their chosen budget. Acknowledged unchanged resumes send
zero repeated memory text; failed/unknown delivery resets the receipt. Selection
uses no model call and no duplicate text index. Candidates piggyback on eligible
explicit durable-decision turns, use quote validation, and clear accepted/dismissed
private text. Recovery reconciles accepted text and metadata.
[Feature guide](../features/project-memory.md).

Still open: fresh/resumed live-provider acceptance, native Memory interaction and
full restart/permission acceptance. Workflow agent steps currently do not add an
automatic project-memory injection; standalone chats keep the compact behavior.

## Second-opinion reviews and fixes

Immutable captures cover combined staged/disk edits, pinned branch comparisons and
recorded turn mutations. Original/modified bytes, hashes, modes when available,
request, selected memory, scope witness and exclusions are frozen and bounded.
Historical input never substitutes current disk. Changed capture witnesses are
rejected. Sensitive, binary and symlink content is visibly excluded.

Review sessions have durable revisioned transitions, stable operation IDs,
existing admission/leases, private partial/final output, cancellation and recovery.
Advisory execution is fresh and has no tools. API/Ollama are the supported source
paths; CLI adapters are disabled. Actual loopback HTTP transport tests verify API and Ollama
review/extraction omit tools and reject forged provider tool calls without using
credentials or paid models. This is not live-provider quality/billing acceptance.

Strict findings require exact supplied-file coverage and narrow captured anchors.
Only validated anchored evidence in a completed re-review resolves an unchanged
prior finding; concurrent dismissal wins. Partial coverage stays Incomplete.

Selected findings can be added to an inspectable composer draft or sent through a
**durable fix queue**. Intents pin finding/review revisions, source/root, current
file/Git witness and displayed implementing provider/model. Busy queues wait for
the ordinary chat lane, then revalidate before dispatch under current approvals.
The request records its actual turn and `review-fix-requested` event. Cancellation,
source deletion, stale inputs and interrupted dispatch have durable outcomes; an
uncertain dispatch is never replayed. Fix claimed requires an applied mutation in
the linked turn/root/finding path, and cannot resolve a finding. The existing
Review surface exposes queue status/cancel, exact input/diff, dismissal, re-review
and safe artifact deletion. [Feature guide](../features/second-opinion-reviews.md).

Still open: representative cross-provider fix/re-review, live usage receipts,
process/permission acceptance. Completed-turn summaries and Workspace source-control/current-file diff actions now open the same review setup with their bound source/root and explicit scope.

## Runnable local workflows

The closed `gyro.workflow.v1` schema supports bounded typed inputs, generic roles,
fixed agent/review/verification steps, named outputs and completion requirements.
Expected-hash native saves use the existing mutation lane; provider/model/command
bindings and values remain private. Unknown versions are preserved disabled.

Typed workflow jobs now use the **existing automation scheduler** for manual and
scheduled runs. Stable operation IDs, exact pinned versions and reviewed schedule
timestamps guard launch/update. Legacy prompt schedules remain available and
unchanged. Unsupported stored workflow configurations cannot fall back to legacy
prompt execution; their records are preserved.

A coordinator persists each step before action, dispatches normal agent turns,
uses owned no-tool review sessions, and runs exact discovered verification tasks
through the existing capability/approval/sandbox/cancellation/receipt path.
Task identity, argv, working directory and manifest fingerprints are bound.
A workflow reserves its checkout before scheduler claim. Ordinary chat/CLI hold
shared kernel leases; workflows require exclusive ownership. Review ownership
prevents standalone recovery from dispatching a coordinator-owned review.
Scheduled child/summary calls retain Automation as their usage origin.

Each run has a 30 minute deadline. Execution completion and requirements are
separate: open findings, incomplete review, failed verification or missing outputs
leave Needs attention. Stop and Pause schedule have separate behavior. Recovery
interrupts uncertain steps without replay and pauses the owning schedule.
Explicit continuation requires inspecting prior actions, acknowledging a new
unfinished-step attempt and rechecking a bounded current workspace witness.
Completed steps are retained in a new linked run. Private run records and
extraction drafts have guarded explicit deletion.

Extraction captures bounded selected-turn evidence with native event IDs, hashes,
redaction and hidden-marker stripping. Cut-off/unfinished sources require an
unproven acknowledgment. An explicitly chosen no-tool provider produces strict
validated JSON for an editable draft; capture, save and launch stay separate.
Cancellation/restart preserve partial output without automatic retry.

Automations now contains **Workflows / Schedules / Runs**, with library/search,
manual editor, explicit setup, extraction inspection, version adoption,
step/approval/output detail, retry inspection and cancellation. Chat options and
completed turns expose Save as workflow. Native/domain logic stays outside React;
App/surfaces/root modules retain thin glue. [Feature guide](../features/workflows.md).

Current execution support is local checkouts and separately opened external
worktrees. Gyro-managed private worktree execution is disabled with an explanation.
Large/non-Git workspaces that cannot produce a bounded retry witness require a
new configured run. Full native sequential execution, restart, tightened policy
and unattended usage acceptance remain open.
