# v0.1.2 local tools: implementation review

2026-11-10. Applied the Agent Design System workflow to the actual Gyro source.
Evidence here is source and synthetic browser rendering, not native acceptance.

## Actual system and placement

Reused Gyro's existing companion/dock, Review destination, Changes comparison,
`PlainDiffView`, native form controls and semantic action patterns. Memory uses
the existing launcher and `/memory`; Review adds local Changes / Second opinion
views. These changes do not introduce new global navigation, a palette, a font
family, Cloud/account controls or another permanent column.

Typography is the existing bundled Geist/Geist Mono system through
`--gyro-font-sans`, `--gyro-font-mono` and support/micro sizes. Surfaces, borders,
focus and text use `--gyro-*` tokens. The kit's sample colors and shadcn list were
not treated as product tokens. Companion width and chat geometry remain owned by
the existing shell.

## Ordered blocks and truthful states

Memory: project root → Entries / Suggestions / Used context → search/list or
editor/detail → source/provenance → settings/receipts. Primary actions are Add or
Save memory in the corresponding state. Search empty, file empty, loading,
unavailable, conflict, unsaved draft, accepting, accepted, dismissed and forgotten
have separate behavior. Escape preserves an active draft; operation results and
errors use status/alert regions. The use switch also disables the dependent
suggestions switch. New projects show the compact 768-byte budget.

Review: Changes / Second opinion → history → root/scope/reviewer/model setup →
captured files/context/exclusions → execution → result/finding list → selected
captured diff → raw input/output and deletion. Capture precedes Start review.
Provider/model selection is explicit and independent of the implementing composer.
API billing and local execution are distinguished in setup. Excluded coverage is
Incomplete. Completed and zero findings never become a green Passed claim.

Findings use compact selectable rows and semantic severity text. Fix requests go
to the normal composer as drafts, require a current-revision choice when stale,
and cannot overwrite an existing draft. A draft is not labeled Sent or Resolved.
Re-review and dismissal remain separate actions. Preview cleanup only deletes
unreferenced input; review deletion keeps snapshots referenced by other runs.

## Findings corrected during review

- Memory's panel box sizing could clip footer controls at constrained height.
  Applied border-box sizing while preserving its existing scroll owner.
- The reused diff component's flex body initially collapsed inside the finding
  detail. Added a scoped bounded height and an assertion that actual hunk rows
  have visible height; inspected the corrected rendering.
- Generic form input sizing centered full-width selection checkboxes. Scoped
  checkbox sizing and row columns now align selection with finding rows.
- Split the Review setup form and Memory detail/editor/settings/receipt blocks
  into focused components. Native/domain work remains outside React.
- Async identity guards, frozen edit hashes, stable launch operation IDs and
  content-free invalidation events prevent late responses from adopting another
  pane's/session's edit base. Re-review comparison uses frozen prior findings.

## Workflow and fix-queue follow-up

The subsequent implementation adds Workflows / Schedules / Runs inside the
existing Automations destination. It uses project selection → library/editor or
extraction → explicit role/input/task setup → schedule/launch → run detail. It
preserves the existing chat geometry and legacy schedules. Save, model extraction
and launch have separate controls; setup has no implicit provider/model choice.
Queued, interrupted, stale version, conflict, unfinished extraction, cancelled and
Needs attention states are distinct. Native save/setup was exercised in the
bundled WebView with a temporary recipe and no model call.

Fix dispatch now has a separate durable queue with cancel and actual turn links.
A completed implementing turn requires recorded applied evidence on the selected
finding path to become Fix claimed; a complete anchored re-review owns resolution.
Completed-turn summaries and Workspace source-control/current-file diff actions
open the same bounded native review setup with their actual source/root scope.
Review and run detail show elapsed time and ledger usage, with explicit estimated
or missing-receipt labels.
