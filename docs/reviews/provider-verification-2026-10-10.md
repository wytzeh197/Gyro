# Gyro provider verification

Checked on 10 October 2026. Every built-in provider has an official integration path, but this machine cannot currently verify all of them with real generation. Grok and a temporary OpenCode installation pass desktop generation, streaming, and session resume. Codex passes CLI generation, including the configured GPT-6 Astra model; the debug desktop build cannot read its Keychain credential. Ollama passes generation, streaming, and Stop after temporarily starting its installed service.

The checks cover the 11 built-in providers. The normal Gyro configuration contains no custom providers. A successful login-status command or ACP handshake is readiness evidence, not proof of model access. Generation passes only when the expected response arrives. These checks do not establish that every model, image input, tool permission, platform, or rendered desktop surface works.

## Implementation checks

All 501 core tests, 63 CLI tests, and four focused desktop ACP tests passed. The live Ollama cancellation test also passed. Provider capability-manifest, identity, streaming-order, and model-catalog checks passed. The initial sandboxed core run could not bind sockets. During verification of the ACP fix, a parallel run had one process-guard lease-test failure; that test passed in isolation and the complete serial core suite then passed with socket access. Both current CLI and desktop debug binaries built successfully.

The shared API transport has fixture coverage for streamed text, fragmented tool calls, compatibility retries, failed/truncated responses, cancellation, and custom endpoints. Those fixtures do not substitute for authenticated DeepSeek, Mistral, or OpenRouter calls. The standalone CLI intentionally cannot execute these three API providers; their real generation checks must use the desktop runner.

The native desktop benchmark drives the real backend chat command in disposable workspaces. It does not measure frontend rendering. Grok and OpenCode timing records include first-token events before provider completion, and their resume records report `resumedActual: true`.

## ACP completion correction

The shared ACP runner previously returned a successful result when a provider stopped with `cancelled` or `refusal`. The [official protocol](https://agentclientprotocol.com/protocol/v1/prompt-turn) defines those separately from normal completion. The runner now routes cancellation through the caller’s cancellation state and refusal through its failure state, while preserving text already streamed.

The core regression test reproduced the incorrect success before the fix and passes afterwards. A real-binary CLI test covers cancellation and refusal for Kimi, Grok, Gemini, Cursor, and OpenCode, checks exit codes 130 and 5 respectively, and verifies that no completed status is saved. Desktop ACP routing and permission tests also pass. This corrects a protocol defect; the original Kimi empty response remains unexplained because its account now rejects authentication.

A fresh readiness recheck still reports Kimi authentication required, Gemini timeout, inaccessible DeepSeek credentials, and missing Mistral/OpenRouter keys. Claude still reports only a stored login. The temporary OpenCode test requires no saved account key and does not install the CLI on the normal PATH.

## Repeat verification

The new verifier enables providers only in a disposable Gyro store, uses the bundled picker defaults, records each readiness result, and makes real CLI calls only with `--live`. It requires the exact expected response and exits unsuccessfully if a provider is blocked, untested, or returns incorrect text. A zero exit code with an empty response no longer counts as a pass in the verifier.

```sh
cargo build -p gyro-cli
node --experimental-strip-types scripts/verify-providers.mjs --output /private/tmp/gyro-provider-readiness.json
node --experimental-strip-types scripts/verify-providers.mjs --live --ollama-model gemma3:4b --output /private/tmp/gyro-provider-live.json
node --experimental-strip-types scripts/verify-providers.mjs --live --providers kimi,ollama --ollama-model gemma3:4b --output /private/tmp/gyro-provider-followup.json
```

Live calls use existing provider accounts and can consume quota. The verifier does not install CLIs, download models, change normal Gyro settings, or repair credentials. Installed CLI versions were Codex 0.162.1, Claude Code 2.1.296, Kimi Code 2.0.2, Gemini CLI 0.63.0, Grok 1.0.50, and Ollama 0.13.5.

Sanitized results, official source URLs, native benchmark records, and the live Stop evidence are saved beside this report in `provider-verification-2026-10-10.json`. Full verification remains open until the account and installation requirements above are resolved.

## Final blocker audit

A final readiness check reproduced Kimi authentication required, Gemini timeout, missing Cursor, inaccessible DeepSeek credentials, and absent Mistral/OpenRouter keys. These setup blockers persisted across three goal turns. Official integration documentation is verified for all 11 providers, but the requirement that every provider works remains incomplete. Full verification is blocked until usable account access and keys are supplied, Cursor is installed, and the desktop credential reader is authorized. Claude’s earlier organization rejection also remains unresolved.
