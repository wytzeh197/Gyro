## Findings

### P0 — the documented verification commands cannot run here

`package.json` requires `pnpm >= 11.0.0`; this machine has 10.30.3 (node
v26.9.0). `pnpm typecheck`, `pnpm check`, `pnpm test:reliability` and
`pnpm doctor` all abort with `ERR_PNPM_UNSUPPORTED_ENGINE` before executing a
single task. Running `tsc` directly works. Fix by pinning the toolchain
(`packageManager` + corepack) or relaxing `engines.pnpm`.

### P1 — one bundle, no code splitting

`apps/desktop/vite.config.ts` defines no `manualChunks` and no dynamic entry
points; the only `import()` in the app is Monaco's grammars
(`editor/monaco-syntax.ts:151`). `App.tsx` and `surfaces.tsx` are each >500 KB
of source by the config's own comment, and settings, browser, terminal and
editor panels are all statically imported into the first chunk. First paint and
steady-state memory pay for every panel, including ones never opened.

Payoff: lazy-loading the four heavy panels behind `React.lazy` + `Suspense`
shrinks the initial chunk and defers Monaco. Risk: medium — needs a deliberate
pass over load order, not a drive-by edit.

### P1 — almost no memoization anywhere

375 declared components, 3 `memo()` calls, 881 inline arrow JSX props, 380
`useState`, 275 `useEffect`, 96 `useMemo`. Chat rows re-render on every streamed
token; without memoized rows and stable callbacks, each token walks the whole
visible transcript.

Payoff: highest of any item here for streaming smoothness. Risk: medium, and it
needs a profile before touching code — memoizing rows whose props are recreated
inline gains nothing.

### P1 — eight independent one-second clocks

22 `setInterval` sites. `chat-run-view.tsx`'s `useNow` starts its own 1s timer
per running header, and `surfaces.tsx` has a separate limit clock. Several
sub-second tickers fire layout work on trees nobody is watching.

Payoff: one shared ticker with per-second granularity removes redundant wakeups
and re-renders. Risk: low-medium, mechanical.

### P2 — CSS carries a lot of duplication

63,524 lines across 47 files; 335 `!important`; 583 `box-shadow:`
declarations; 162 `transition:`; 113 `animation:`; 38 `backdrop-filter`.
Repeated selector blocks: `.gyro-settings-surface` ×16, `.gyro-browser-frame`
×11, `.gyro-editor-statusbar` ×10, `.gyro-command-palette` ×10,
`.gyro-chat-composer-dock` ×10, then ×9/×8 for seven more.

Not all of this is dead — layered overrides are a legitimate pattern — but 16
declarations of one selector means the cascade is being negotiated in the
stylesheet. Consolidation is worth a dedicated pass with visual regression
checks, not a blind dedupe.

### P2 — four files hold a third of the codebase

`styles.css` 44,443 + `lib.rs` 32,217 + `surfaces.tsx` 31,069 + `App.tsx`
20,472 = 128,201 lines in four files. The Vite config already
carries a warning that Babel deoptimizes `App.tsx`/`surfaces.tsx` and can stall
the dev server for minutes, which is why SWC is wired in. This is the main drag
on editing speed and review quality.

### P2 — Rust panic and copy surface in the desktop bridge

`apps/desktop/src-tauri/src/lib.rs` contains 676 `unwrap()`/`expect(` calls, and
`apps/desktop/src-tauri/src/*.rs` contains 1,122 `.clone()` calls across 21
files that also use `std::fs::`. A malformed IPC payload reaching one of those
`unwrap`s takes the window down instead of returning an error; buffer clones on
the IPC path cost memory per message. Neither is a bug today — both are a
standing invitation for one.

## Suggested order

1. Fix the toolchain contract (P0) — until then the gates documented in
   `README` cannot be run at all.
2. Memoize chat rows after a profile (P1, biggest UX payoff).
3. Lazy-load settings/browser/terminal/editor (P1, biggest startup payoff).
4. One shared clock (P1, low risk, do it alongside 2).
5. CSS consolidation and `lib.rs` split as dedicated follow-ups (P2).
