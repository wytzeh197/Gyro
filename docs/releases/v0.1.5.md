# Gyro v0.1.5

Gyro 0.1.5 improves recovery for unsaved drafts, chat sessions and settings.
Remote workspaces preserve newer edits during reloads, renames and deletions,
and handle large Unicode terminal pastes. Workspace and attachment reads gain
stronger validation, while Git status, change summaries and device activity
writes do less repeated work.

## What changed

- Editor drafts survive recoverable storage failures. Remote draft recovery
  preserves newer edits and does not revive files renamed or removed while
  startup storage is loading. A completed host deletion retains text typed
  after confirmation so it can still be copied.
- Chat sends handle cancellation during preparation, session-list failures can
  be retried, and a completed response preserves a model selection made while
  it was running. Chat settings must save successfully before a send proceeds.
- Settings show save failures with a retry action. If configuration cannot be
  loaded, retry loading or explicitly back up the file and reset to safe
  defaults; chats, projects and stored credentials are retained.
- Remote terminal input splits large Unicode pastes into ordered, bounded
  chunks. Interactive operations receive priority during background refreshes.
  Terminal output tracks byte positions across history rollover and restarts.
- Remote catalog refreshes retain requests arriving during an existing refresh
  and combine events from multiple hosts. Remote Access settings show recent
  device activity without recording prompts, file contents or terminal input.
- Workspace reads on macOS bind to authorized directories and refuse unsafe
  file substitutions. Attachment consumers recheck size and supplied content
  hashes. Git blame uses captured file bytes and isolated repository metadata.
- Confined workflow workers count macOS memory footprint as well as resident
  memory when enforcing their existing 256 MiB memory budget.
- File-change approval cards require loading the change preview before approval.
  Secondary Explorer actions move into a More menu.
- Concurrent Git detail reads share work, change counts and retained patches
  share a diff calculation, and repeated device activity writes avoid redundant
  pruning.

## Download and install

Requires macOS 14+ on Apple Silicon or Intel. Public stable app bundles and
DMGs must be signed with Gyro's Developer ID and notarized by Apple. These are
the intended release links; v0.1.5 artifact acceptance is still pending:

- [Download site](https://usegyro.io/)
- [Apple Silicon: Gyro_0.1.5_aarch64.dmg](https://github.com/wytzeh197/Gyro/releases/download/v0.1.5/Gyro_0.1.5_aarch64.dmg)
- [Intel: Gyro_0.1.5_x64.dmg](https://github.com/wytzeh197/Gyro/releases/download/v0.1.5/Gyro_0.1.5_x64.dmg)
- [SHA256SUMS](https://github.com/wytzeh197/Gyro/releases/download/v0.1.5/SHA256SUMS)

Match the checksum to the exact filename. Follow
[docs/install-macos.md](https://github.com/wytzeh197/Gyro/blob/main/docs/install-macos.md).
When a Developer ID build first replaces an ad-hoc installation, macOS may
require Accessibility permission again and display a one-time Keychain prompt.

## Behavior and known limits

Local work and user-owned provider connections do not require a Gyro account.
Hosted sign-in, purchases, uploads, sharing and managed AI remain disabled in
the default build. This release does not activate Cloud services.

Remote access remains experimental. Both Macs need compatible builds. Physical
two-Mac operation, WAN reconnect and a live provider run across the pair still
require release acceptance. SSH uses existing key/agent authentication and
trusted host keys; interactive password prompts are unsupported. See
[Remote access over SSH](../features/remote-access-ssh.md).

Automated fixtures do not establish installed-app upgrade, clean-user
Gatekeeper, signed-updater or hardware sleep/wake acceptance. These checks must
be completed against the exact packaged release before publication. File-read
race protections described above were tested on macOS/Unix; the non-Unix
fallback does not offer equivalent descriptor-relative protection. Isolated
Git blame does not apply custom repository configuration such as mailmap
overrides; other Git diff operations can still honor configured clean filters.

Live cross-provider handoff, annotated visual-fix and extracted-workflow reuse
acceptance remain outstanding. Provider support depends on the installed
provider, account, model and configuration; Cursor and OpenCode remain
experimental. No new live provider savings or WAN latency claim is made.

## Upgrade and rollback

Quit Gyro and back up `~/Library/Application Support/Gyro/` and project `.gyro/`
directories before upgrading or rolling back. After publication, install the
matching DMG or use the signed updater. Verify retained sessions, provider
access, drafts, project memory and workflows before removing the backup.
Keyring-only Codex accounts may need to sign in once for Gyro's private
Codex home.

For rollback, quit Gyro and reinstall
[v0.1.4](https://github.com/wytzeh197/Gyro/releases/tag/v0.1.4). The updater does
not downgrade. Restore the matching data backup if the older build cannot
read newer data; cross-version downgrade acceptance has not been established.

## CLI

Keep CLI and app versions aligned when handing sessions between them:

- [Apple Silicon CLI](https://github.com/wytzeh197/Gyro/releases/download/v0.1.5/gyro-cli-0.1.5-aarch64-apple-darwin.tar.gz)
- [Intel CLI](https://github.com/wytzeh197/Gyro/releases/download/v0.1.5/gyro-cli-0.1.5-x86_64-apple-darwin.tar.gz)

Each archive requires a `.sha256` sidecar. Release finalization generates the
checksummed `gyro.rb` Formula; the repository template is not a published tap
update. Homebrew installs the CLI only. After the Formula has been published:

```bash
brew tap wytzeh197/tap
brew install wytzeh197/tap/gyro
```
