# Gyro v0.1.0

This release repairs clean-checkout installation and verification, brings Account, Plan & billing and Cloud onto one native session, and keeps local work and user-owned providers available without signing in. Account, Plan & billing and Cloud remain visible as coming-soon settings. Sign-in, subscriptions and hosted features are disabled in this release; local work and your own providers remain available.

## Release identity

App and CLI version: 0.1.0. Immutable launch tag: v0.1.0-launch.20261106. The pre-existing July v0.1.0 tag and published preview assets are preserved. Updater manifests report 0.1.0 and link to this launch tag. Stable release distribution requires Developer ID signing and notarization.

## Cloud availability

Account, Plan & billing and Cloud settings are visible with a Coming soon state. Sign-in, subscription purchase, uploads, sharing and managed AI are disabled. Cloud stays out of the standard workspace sidebar. The native production adapter is not constructed, saved credentials are not restored, and these pages make no hosted request. Local work, the CLI and user-owned provider connections remain available without an account.

`config/cloud-availability.json` records this release choice separately from the verified production infrastructure. Enabling Cloud later requires a separately reviewed app/service release; server availability alone cannot activate it in this build. Future subscription preparation is personal-use only.

## Download and install

After release approval and publication, download from https://usegyro.io/. Choose `Gyro_0.1.0_aarch64.dmg` for Apple Silicon or `Gyro_0.1.0_x64.dmg` for Intel, and verify `SHA256SUMS`. Requires macOS 14+. See [the macOS installation guide](../install-macos.md) (`docs/install-macos.md`). Public stable artifacts must be Developer ID signed and notarized by Apple; the local development bundle is ad-hoc signed.

## Upgrade and rollback

Back up local data before switching builds. The updater accepts only a strictly newer app version and does not install the older July build or preview. This candidate is app version 0.1.0 under a distinct immutable launch tag; it does not replace the July tag. Rollback is an explicit manual installation from a reviewed prior release, never an automatic downgrade.

## CLI

The launch includes separate Apple Silicon and Intel CLI archives, a generated Homebrew Formula, and deterministic checksum verification. Install only after publication from the launch release's exact tag. A source build can run `cargo build --locked -p gyro-cli`; packaging verification runs the packaged binary and rejects modified archives.

Clients from the July build already report 0.1.0. They need a manual installation of this launch build because an equal version is deliberately not treated as an automatic update. Preview.3 clients can update to 0.1.0 after publication.

## Install this branch from source before publication

Use the branch `refs/heads/v0.1.0`, rather than the historical `v0.1.0` tag. This continuation was verified on an Apple Silicon (`arm64`) Mac. Intel package verification and the full native Intel Rust suite remain release gates. Keep the checkout outside iCloud-synced folders and preserve existing checkouts with local work.

With Node **22.23.1**, pnpm **11.7.0**, Rust and the Xcode command line tools installed:

```sh
mkdir -p ~/Developer
git clone --branch v0.1.0 --single-branch https://github.com/wytzeh197/Gyro.git ~/Developer/Gyro-v0.1.0
cd ~/Developer/Gyro-v0.1.0
git rev-parse HEAD
node --version
pnpm --version
CI=1 pnpm install --frozen-lockfile
CI=1 pnpm doctor
CI=1 pnpm desktop:bundle
```

If that destination already exists, inspect its branch, upstream and dirty/untracked state before fetching; use a fast-forward only when safe, or create a separate worktree. Do not reset or clean it. The bundle command uses `Cargo.lock` with `--locked` and builds `target/release/bundle/macos/Gyro.app`; it does not replace the running installation.

Before installing, quit Gyro and back up the current app and `~/Library/Application Support/Gyro/`. Run `node scripts/install-local-app.mjs` from this checkout to copy the bundle to `~/Applications/Gyro.app` and open it. This is a local development build; public stable distribution still requires the approved signing, notarization and publication workflow.

Account appears without a bundle override. Cloud stays out of the standard sidebar and is accessed through Settings. Cloud is deliberately disabled by the committed release setting, independently of the prepared production configuration. Installing from source does not enable sign-in or charging. Existing public preview downloads and the July tag have not been replaced.

## Continuation verification on 2026-11-04

Verified from an isolated branch worktree on arm64 macOS 26.2 with Node 22.23.1 and pnpm 11.7.0: frozen dependency installation, typecheck, full Node suite, workbench/style budgets, release/download checks, Cargo formatting, 1,931 Rust tests passed with 14 existing ignored, locked native bundle build, CLI packaging, and Canvas browser regression. A separate debug verification bundle passed 17 native browser checks and 3 LSP checks. Native UI inspection confirmed Account, Plan & billing, Cloud access through Settings, no Cloud item in the standard sidebar, and account-free quit/restart with production unconfigured. Test data and the verification app identity were isolated; the running user installation was preserved.

These are local build and acceptance results. They do not establish Intel installation, public signing/notarization, hosted authentication/Keychain restore, subscription fulfillment or a paid provider request.

## Packaging verification

The first 5 November build was notarized but its verifier failed during mounted-DMG cleanup; its immutable tag is preserved unpublished. This candidate retries transient busy detaches and never removes a still-mounted volume or masks the original verification error.

The next Intel build also received Apple acceptance, but Apple’s ticket service dropped the connection during stapling. This candidate adds bounded ticket retries and preserves signed builds as intermediate artifacts. Compilation runs on Apple Silicon; the complete native Intel Rust suite runs in parallel, and final app/DMG and CLI packages are verified on their actual CPU architecture before one complete draft can be assembled. Failed verification jobs can reuse the signed build without repeating compilation. No signing, notarization or native-test requirement is waived.
