# Gyro v0.1.0-alpha.36

Gyro Alpha 36 lets the model start a long-running task in the background
instead of holding the turn open until it exits, hosts Changes and Terminal
inside the chat's side pane, and keeps mid-run narration off the final answer
when a closing sentence announces the next step.

## Download and install

Gyro requires macOS 14+ and is not Apple-signed or notarized. The application
uses a complete ad-hoc signature, so the first launch still requires Apple's
one-time **Open Anyway** approval.

Use the [Gyro download site](https://usegyro.io/) to select the correct build,
then follow the
[macOS installation guide](https://github.com/wytzeh197/Gyro/blob/main/docs/install-macos.md).
Do not disable Gatekeeper or remove quarantine globally.

- [Apple Silicon DMG](https://github.com/wytzeh197/Gyro/releases/download/v0.1.0-alpha.36/Gyro_0.1.0-alpha.36_aarch64.dmg)
- [Intel DMG](https://github.com/wytzeh197/Gyro/releases/download/v0.1.0-alpha.36/Gyro_0.1.0-alpha.36_x64.dmg)
- [SHA256SUMS](https://github.com/wytzeh197/Gyro/releases/download/v0.1.0-alpha.36/SHA256SUMS)

## What changed

- **Background tasks stop freezing the turn.** `gyro_workspace_run_task` and
  `gyro_workspace_run_test` take `background: true`, which starts the task in
  this chat's terminal and returns immediately. A dev server or watcher no
  longer holds the turn open until it exits, which is what made a working chat
  look like it had stopped mid-run.
- **Background tasks are readable and stoppable.** A backgrounded task claims
  the same model-owned terminal as `terminal.open`, so it is read with
  `gyro_terminal_read`, ended with `gyro_terminal_stop`, and covered by the
  existing Terminal Execute permission class — no new approval surface.
- **Changes and Terminal open in the side pane.** Picking either tool takes the
  right pane over in place, with a header that goes back to the launcher,
  rather than closing the pane the user just opened.
- **Closing sentences no longer become the answer.** A block that ends by
  committing to the assistant's own next move ("The strip is back. Now let me
  look at the recording.") is treated as rail narration, not the final answer.

## Behavior changes and known limits

- Alpha app bundles remain ad-hoc signed and not notarized.
- Existing Alpha 35 sessions remain compatible; no destructive data migration
  is required.
- A chat still owns at most one model terminal, so a background task and
  `terminal.open` compete for the same slot. Stop the running one before
  starting another.
- A backgrounded task does not update the Workspace output channel; read its
  output through the terminal instead of `gyro_workspace_read_output`.
- Background is opt-in per call. A task run without it behaves exactly as
  before, including the full captured stdout and stderr in the result.

## Upgrade and rollback

Alpha 35 data remains compatible with Alpha 36. Update from Gyro or replace
the application with the matching Alpha 36 DMG.

Before changing versions, quit Gyro and back up
`~/Library/Application Support/Gyro/`. To roll back, reinstall
[`v0.1.0-alpha.35`](https://github.com/wytzeh197/Gyro/releases/tag/v0.1.0-alpha.35).

## CLI

The CLI remains version-aligned with the app. After the release Formula reaches
the tap:

```bash
brew tap wytzeh197/tap
brew install wytzeh197/tap/gyro
```

Direct archives are available for
[Apple Silicon](https://github.com/wytzeh197/Gyro/releases/download/v0.1.0-alpha.36/gyro-cli-0.1.0-alpha.36-aarch64-apple-darwin.tar.gz)
and
[Intel](https://github.com/wytzeh197/Gyro/releases/download/v0.1.0-alpha.36/gyro-cli-0.1.0-alpha.36-x86_64-apple-darwin.tar.gz).

## Alpha notice

This is a GitHub-built public macOS Alpha for Apple Silicon and Intel. Updater
archives are signed with Gyro's updater key, while application bundles use
ad-hoc code signing and DMGs are not Apple-signed or notarized.
