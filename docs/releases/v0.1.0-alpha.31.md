# Gyro v0.1.0-alpha.31

Gyro Alpha 31 adds usage safety: a local ledger that records what every
provider call actually spent, a cost preview before a fan-out send commits it,
and guardrails that stop a runaway loop or an unattended schedule before it
drains a plan. It also introduces Model Council — several models answering the
same question in parallel with a synthesized result — and simplifies the chat
slash menu.

## Download and install

Gyro requires macOS 14+ and is not Apple-signed or notarized. The application
uses a complete ad-hoc signature, so the first launch still requires Apple's
one-time **Open Anyway** approval.

Use the [Gyro download site](https://usegyro.io/) to select the correct build,
then follow the
[macOS installation guide](https://github.com/wytzeh197/Gyro/blob/main/docs/install-macos.md).
Do not disable Gatekeeper or remove quarantine globally.

- [Apple Silicon DMG](https://github.com/wytzeh197/Gyro/releases/download/v0.1.0-alpha.31/Gyro_0.1.0-alpha.31_aarch64.dmg)
- [Intel DMG](https://github.com/wytzeh197/Gyro/releases/download/v0.1.0-alpha.31/Gyro_0.1.0-alpha.31_x64.dmg)

## What changed

- **Usage is recorded locally, per provider call.** Gyro writes its own ledger
  rather than trusting each CLI to report spend: one row per call, tagged with
  what asked for it. A Council turn appears as its seats plus the synthesis,
  not as a single turn, because that gap is how quota disappears unexplained.
  Providers that report no token counts are estimated and labelled as
  estimates — never blended into a number that looks measured.
- **Chats show what they cost.** The composer carries a running
  `1.2M tokens · 14 calls` line for the current chat, with a hover breakdown by
  origin (chat, council seats, synthesis, automations).
- **Expensive sends are disclosed before they are committed.** Council mode
  shows the multiplier up front — `5 calls · ~264K tokens · 5× a normal turn` —
  and a send large enough to matter has to be agreed to rather than merely
  displayed. Fan-out at `max`/`ultra` effort, any multi-call send above ~400K
  tokens, and a send that dwarfs what the chat has been spending all ask first.
- **Guardrails stop what nobody chose.** Ceilings on call rate, on unattended
  automation runs, on Council re-syntheses, and on tokens billed by a single
  call. A call that passes its ceiling is stopped through the same path as the
  stop button, so partial work is still saved and the spend still recorded.
- **Budgets, with a pause that explains itself.** Per-provider caps over a
  rolling window notify at 70%, hold Council runs and automations at 90% while
  ordinary turns continue, and stop that provider at 100%. An exhausted budget
  pauses Gyro with its reason recorded and lifts by itself when the window
  rolls; a manual pause has no expiry and is never overwritten by an automatic
  one.
- **Model Council.** Several ready providers answer the same frozen context in
  parallel, then a synthesizer produces one structured result with agreements,
  disagreements, and adoption steps. Seats are read-only and cannot mutate the
  workspace.
- **Simpler slash menu.** Chat commands are single-line rows — command, then a
  short label — with the header and keyboard-hint chrome removed. Commands
  whose behaviour is not self-evident carry a `?` that explains them in plain
  language on hover.
- **Grok reasoning effort.** xAI models expose the low/medium/high levels Grok
  publishes, defaulting to high. Levels Grok does not accept are dropped rather
  than sent for the model to reject.

## Behavior changes and known limits

- Budgets are enforced and displayed but can only be created by editing
  `usageGuard.budgets` in the config file; Settings has no editor yet. With no
  budget configured, the budget layer is inert and only the fixed guardrails
  apply.
- Resuming a pause is available from the composer banner; starting one by hand
  is not yet exposed in the UI.
- Token counts for Kimi, xAI, and Gemini are estimated from message length,
  because those CLIs report no usage. Ledger totals for those providers are
  approximate and marked as such.
- Council seats cannot use tools, so a council answer reasons about the frozen
  context rather than exploring the workspace.
- Gemini's ACP agent exposes no reasoning-effort control, so no effort chip is
  offered for it.
- The ledger has no retention policy in this release; it grows by one small row
  per provider call.
- Existing Alpha 30.5 sessions, projects, settings, and editor state remain
  compatible; no destructive data migration is required.

## Upgrade and rollback

Alpha 30.5 data remains compatible with Alpha 31. The usage ledger table is
created on first launch and starts empty, so cost lines fill in as new turns
run. Update from Gyro or replace the existing application with the matching
Alpha 31 DMG.

Before changing versions, quit Gyro and back up
`~/Library/Application Support/Gyro/`. To roll back, reinstall
[`v0.1.0-alpha.30.5`](https://github.com/wytzeh197/Gyro/releases/tag/v0.1.0-alpha.30.5).

## CLI

The CLI remains version-aligned with the app. After the release Formula reaches
the tap:

```bash
brew tap wytzeh197/tap
brew install wytzeh197/tap/gyro
```

Direct archives are available for
[Apple Silicon](https://github.com/wytzeh197/Gyro/releases/download/v0.1.0-alpha.31/gyro-cli-0.1.0-alpha.31-aarch64-apple-darwin.tar.gz)
and
[Intel](https://github.com/wytzeh197/Gyro/releases/download/v0.1.0-alpha.31/gyro-cli-0.1.0-alpha.31-x86_64-apple-darwin.tar.gz).

## Alpha notice

This is a GitHub-built public macOS Alpha for Apple Silicon and Intel. Updater
archives are signed with Gyro's updater key, while application bundles use
ad-hoc code signing and DMGs are not Apple-signed or notarized.
