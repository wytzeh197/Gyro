# Gyro v0.1.0-alpha.39

Gyro Alpha 39 makes Run and Test work on real projects instead of a hardcoded
handful, gives every connected provider a measured usage reading, and ships a
quieter typography and color pass that no longer depends on a font CDN.

## Download and install

Gyro requires macOS 14+ and is not Apple-signed or notarized. The application
uses a complete ad-hoc signature, so the first launch still requires Apple's
one-time **Open Anyway** approval.

Use the [Gyro download site](https://usegyro.io/) to select the correct build,
then follow the
[macOS installation guide](https://github.com/wytzeh197/Gyro/blob/main/docs/install-macos.md).
Do not disable Gatekeeper or remove quarantine globally.

- [Apple Silicon DMG](https://github.com/wytzeh197/Gyro/releases/download/v0.1.0-alpha.39/Gyro_0.1.0-alpha.39_aarch64.dmg)
- [Intel DMG](https://github.com/wytzeh197/Gyro/releases/download/v0.1.0-alpha.39/Gyro_0.1.0-alpha.39_x64.dmg)
- [SHA256SUMS](https://github.com/wytzeh197/Gyro/releases/download/v0.1.0-alpha.39/SHA256SUMS)

## What changed

- **Run and Test discover the commands your project actually has.** Task
  discovery reads `package.json` scripts (with the runner picked from the
  lockfile), Cargo, Makefiles, justfiles, and Python, Go, and Deno projects,
  instead of offering package scripts plus two Cargo tasks. The Test tree is
  built from the same discovery, so test commands come from the same source of
  truth as Run.
- **You can save your own commands.** Custom commands persist to
  `.gyro/tasks.json` in the workspace. A typed command line is split without a
  shell and spawned directly, and saved commands flow through the same
  discovery path, so the existing "task definition changed" tamper check still
  guards every run. Runs honor a task's working directory and can be cancelled
  from the row that started them.
- **The task sidebar reads like a list of commands.** Tasks group by source and
  kind, each row shows its command line, a running row becomes a stop control,
  long lists filter, and the debug-adapter launcher moved to its own section.
- **Every connected provider shows measured usage.** Anthropic plan windows now
  come from the account usage endpoint (with `rate_limit_event` frames as the
  mid-answer fallback), xAI reports its weekly credit window, and Kimi answers
  with one row per metered window. Providers with no plan-window API fall back
  to local ledger spend rather than an invented number: composer limit rows and
  the Settings → Usage Limits cards label those "· local".
- **Kimi K3 is described honestly.** The context window is 256K, not a
  megatoken — the old number made the composer meter measure against a window
  the run never had. Thinking effort offers low, high, and max with high as the
  default, matching what the Kimi Code service actually accepts.
- **Typography and color pass.** Inter and Inter Tight ship inside the app as
  vendored latin subsets, so the desktop app loads no font CDN. Dark and light
  surfaces were retuned together, the early shell and error screen match the
  app they load into, and the code editor finally has a real light theme
  instead of a dark editor on a light window. `pnpm smoke:workbench` now runs a
  token check that fails if these drift apart again.

## Behavior changes and known limits

- Alpha app bundles remain ad-hoc signed and not notarized.
- Existing Alpha 38 sessions remain compatible; no destructive data migration
  is required.
- Custom commands live in the workspace at `.gyro/tasks.json`, not in app data.
  They travel with the repository, so treat them as checked-in configuration
  and review them the way you would review any other command in the tree.
- Task discovery reads manifests; it does not execute them. A discovered
  command still runs only when you start it, and editing a task definition
  outside Gyro re-triggers the tamper check.
- Usage windows are only as good as what a provider reports. Gemini still has
  no plan-window API, so its reading is local ledger spend only. A missing
  reading stays unfilled rather than showing a guess.
- Budgets are still enforced and displayed but not yet editable in Settings,
  and the "where it went" origin breakdown is still unrendered.

## Upgrade and rollback

Alpha 38 data remains compatible with Alpha 39. Update from Gyro or replace
the application with the matching Alpha 39 DMG.

Before changing versions, quit Gyro and back up
`~/Library/Application Support/Gyro/`. To roll back, reinstall
[`v0.1.0-alpha.38`](https://github.com/wytzeh197/Gyro/releases/tag/v0.1.0-alpha.38).
A `.gyro/tasks.json` written by Alpha 39 is ignored by Alpha 38 rather than
breaking it.

## CLI

The CLI remains version-aligned with the app. After the release Formula reaches
the tap:

```bash
brew tap wytzeh197/tap
brew install wytzeh197/tap/gyro
```

Direct archives are available for
[Apple Silicon](https://github.com/wytzeh197/Gyro/releases/download/v0.1.0-alpha.39/gyro-cli-0.1.0-alpha.39-aarch64-apple-darwin.tar.gz)
and
[Intel](https://github.com/wytzeh197/Gyro/releases/download/v0.1.0-alpha.39/gyro-cli-0.1.0-alpha.39-x86_64-apple-darwin.tar.gz).

## Alpha notice

This is a GitHub-built public macOS Alpha for Apple Silicon and Intel. Updater
archives are signed with Gyro's updater key, while application bundles use
ad-hoc code signing and DMGs are not Apple-signed or notarized.
