# Gyro v0.1.4

Release candidate notes. Publication and signed artifact acceptance are pending.

Gyro 0.1.4 adds experimental remote Mac workspaces, improves session and
storage recovery, and connects build and test failures to the coding workflow.

## What changed

- Experimental remote access supports Gyro pairing and existing SSH setups.
  Shared projects use the normal sidebar, composer, live chat, files, Git,
  terminal and approval surfaces. Both Macs need compatible builds.
- Build and test tasks publish supported compiler diagnostics to Problems after
  the command finishes. Locations open the source file; Send to chat attaches
  a diagnostic to an editable draft. Rerunning clears that task's old findings.
  Other tasks and language-server findings stay separate.
- The first-run tour offers an optional first-task draft. It asks the agent to
  propose a small change and verification plan before editing. Choosing it
  preserves existing drafts and does not submit a prompt.
- Codex uses Gyro's private thread and database storage. Existing Gyro
  transcripts remain available; the first continuation of an older shared
  thread uses Gyro conversation context rather than migrating hidden Codex state.
- Editor improvements include auto-save, document symbols and additional
  formatting/navigation controls. Persistence safeguards improve session,
  SQLite and CLI spill recovery.
- Check requirements, evidence freshness, model-switch context and reusable
  workflow recipes receive stronger validation. An agent's completion message
  does not become an independent verification result.
- Startup recovery now also handles a failed remote-access module load.
  Additional remote, Environment, Usage and Check regressions run in CI.

## Behavior and known limits

Local work and user-owned provider connections do not require a Gyro account.
Hosted sign-in, purchases, uploads, sharing and managed AI remain disabled in
the default build. This release preparation does not activate Cloud services.

Remote access remains experimental. Physical two-Mac operation and a new live
provider run across the pair still require release acceptance. SSH uses existing
key/agent authentication and trusted host keys; interactive password prompts
are unsupported. See [Remote access over SSH](../features/remote-access-ssh.md).

Task diagnostics cover TypeScript, Rust and common file:line compiler formats;
unknown formats remain in Output. Diagnostics arrive when bounded tasks finish,
not while a dev-server terminal is streaming. A clean Problems panel alone is
not proof that tests passed. Automated code actions are not included.

Live cross-provider handoff, annotated visual-fix and extracted-workflow reuse
acceptance remain outstanding. Efficiency experiments have no new live savings
claim and their defaults are unchanged. Provider support depends on the installed
provider, account, model and configuration; Cursor and OpenCode remain experimental.

## Upgrade and rollback

Quit Gyro and back up `~/Library/Application Support/Gyro/` and project `.gyro/`
directories before upgrading or rolling back. Install the matching DMG or use
the signed updater after publication. Verify retained sessions, provider access,
project memory and workflows before removing the backup. Keyring-only Codex
accounts may need to sign in once for Gyro's private Codex home.

For rollback, quit Gyro and reinstall
[v0.1.3](https://github.com/wytzeh197/Gyro/releases/tag/v0.1.3). The updater does
not downgrade. Restore the matching data backup if the older build cannot read
newer data; cross-version downgrade acceptance has not been established.

## CLI

Keep CLI and app versions aligned when handing sessions between them:

- [Apple Silicon CLI](https://github.com/wytzeh197/Gyro/releases/download/v0.1.4/gyro-cli-0.1.4-aarch64-apple-darwin.tar.gz)
- [Intel CLI](https://github.com/wytzeh197/Gyro/releases/download/v0.1.4/gyro-cli-0.1.4-x86_64-apple-darwin.tar.gz)

Each archive requires a `.sha256` sidecar. Release finalization generates the
checksummed `gyro.rb` Formula; the repository template is not a published tap
update. Homebrew installs the CLI only.
